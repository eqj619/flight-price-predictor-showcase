# 価格曲線の実測（2026-08-15）

**212系列 / 13,004点。** 取得元が応答に載せていた過去約61日分を、稼働中223ルートに
遡って取り込んだもの（`price_history`）。課題2・3のパラメータ再推定の材料。

## 測り方と、その限界

**履歴は1系列あたり約61日しかない。** 出発 D 日後のルートで見えるのは
「出発 D 日前 〜 D+60 日前」の窓だけで、それ以外は原理的に観測できない。

この打ち切り（censoring）を無視すると、**同じデータから正反対の結論が出る。**

| 見方 | 出る答え | なぜ間違いか |
|---|---|---|
| 全212系列で最安の時期を数える | 窓に入るのは 26%。中央値は出発120日前 | 遠い出発日の系列は45〜75日前を**まだ観測していない**のに「該当なし」と数えている |
| 窓を完全に覆う35系列だけ | 窓に入るのは 74%。中央値は出発57日前 | 近い出発日の系列は100日前を**もう観測できない**。逆向きの打ち切り |

**どちらも答えになっていない。** 正しくは、系列ごとに区間どうしを比べ、
**系列を標本単位として**数える（1系列61点は強く相関するので、13,004点を
独立扱いしてはいけない）。

## 結果 — 系列ごとの対比較

| 比較 | 前者が安い系列 | 価格比の中央値 | 符号検定 |
|---|---|---|---|
| 窓(45–75日前) vs **それ以前**(76–200日前) | 32/66（48%） | **+0.6%** | z=−0.2 |
| **最安帯(50–59日前)** vs それ以前 | 29/40（72%） | **−4.2%** | z=+2.8 |
| **窓(45–75日前) vs 直前(10–30日前)** | **35/41（85%）** | **−16.7%** | **z=+4.5** |

**読み取れること:**

1. **モデルの「45〜75日前が底」は、窓としては広すぎる。** それ以前（76〜200日前）
   と比べて差が無い（z=−0.2）。**この幅を目がけて待つ意味は無い。**
2. **50〜59日前には実在の谷がある（−4.2%, z=+2.8）。** 窓を絞れば有意。
   「安くなる時期は無い」とは言えない。
3. **圧倒的に効くのは、出発30日前を過ぎないこと。** +16.7%、85%の系列で一致。
   谷の深さの4倍。**このアプリが伝えるべき一番の情報はこれ。**

## モデルと実測の突き合わせ

| 40–49 | 0.918 | 1.004 | |

| 60–69 | 0.910 | 0.965 | |
| 70–79 | 0.911 | 0.998 | |

早く買っても損はしない。ここが対比較で差が出なかった原因。

## 推定した曲線（適用済み）

`scripts/fit_curve.py` で推定し、`app/predict/curve.py` の既定値に反映した。

**素朴に「系列ごとに自分の平均で割って重ねる」ことはしない。** 系列ごとに
見えている区間が違うので、基準がそろわず系列構成の偏りが傾きに乗る。
代わりに log 価格を「系列効果 ＋ 出発までの日数の効果」に分解した（二元固定効果）。
区間が重なり合う系列どうしが互いの水準を結び付け、どの系列も単独では
見ていない全体の形が復元される。

### 「底値帯は無い」は言い過ぎだった（2026-08-17 訂正）

当初この節には「底値帯は無い」と書いた。**誤り。** 区間を絞った対比較では
谷が有意に出る。

| 比較 | 結果 |
|---|---|
| 45–75日前 vs 76–200日前 | 32/66（48%）, +0.6%, z=−0.2 → **差を言えない** |
| **50–59日前 vs 76–200日前** | **29/40（72%）, −4.2%, z=+2.8 → 有意に安い** |
| 45–75日前 vs 100–200日前 | 16/41（39%）, +3.5%, z=−1.4 → 差を言えない |
| 160–200日前 vs 60–120日前 | 16/23（70%）, −6.7%, z=+1.9 → 有意に届かない |

正しくは **「旧モデルの45〜75日という窓が広すぎた」**。窓の中に安い部分
（50〜59日）と安くない部分（45〜49日、60〜75日）が混ざり、平均すると差が
消えていた。

**谷は実在するが浅い。** そして遅延の罰（+16.7%）はその4倍。10日の窓を
当てに行って外し、30日前を割れば、−4%を取りに行って +17% を払う。
**助言としては「遅らせるな」が正しいが、「安くなる時期は無い」は事実として誤り。**

なお、当てはめで残った窓 52〜59 の谷は −0.5% で、上の −4.2% と食い違う。
**区間比較のほうが直接的な測定**で、当てはめは全区間を1つの式で同時に
説明しようとした結果、谷が浅く出ている。式の表現力の限界。

### 推定できなかったもの

- **`last_minute_peak_factor`（当日）は触っていない。** 出発5日前より内側の
  観測が1点も無い。15〜20日前でも数十点。推定したふりをしない
- **165日前より前の谷（実測 0.95）は表現できない。** `far_taper_amount` に
  負値を許して探索させたが 0 が選ばれた。「底値帯から直線」というこの式では、
  60〜160日前の平坦部を壊さずに遠方だけ下げられない。**式の限界**

### 振る舞いが変わった点

**出発200日前の判定が `wait` → `buy_now` になった。** 曲線が平坦になったので
「底値帯まで待つ」根拠が消えた。待っても得るものが無く、取り逃す危険だけが増える。

**画面の文言も 2026-08-16 に反転させた。** 緑の「底値帯」を橙の
「ここから上がる」に変え、買い時分析に値上がり開始日を出している。
2026-08-17 に、谷が実在することを根拠欄へ書き足した
（「待っても安くならない」と言い切らない）。

## この材料の弱点

- **系列は「その検索条件での最安値」で、便を特定しない。** 便の入れ替わりを含む
  （日次 5.27% 動く。同一便なら 1.61%）。谷の深さ −4% はこの雑音と同程度で、
  **谷の存在は言えても深さの精度は低い**
- 61日窓のため、**1系列だけでは全体の形を見られない。** 上の曲線は出発時期の
  違う系列を重ねて復元したもの
- 200日前より先は系列数が減る（n=50〜300）。**300日前の +9% は当てにならない**
- 路線が米西海岸⇄東京に偏っている（課題11）。**季節性と混ざっている可能性**が残る
