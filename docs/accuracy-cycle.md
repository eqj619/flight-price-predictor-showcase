# 予測精度を上げる回し方（2026-08-24 制定）

**思いつきで曲線を触らないための手順。** 課題2で一度「未検証のモデルを
判定に使う」失敗をしており、課題9でその実害（出発直前の予測が +16.9%）が
実測で確認された。同じことを繰り返さないよう、順番を固定する。

## 原則

**1. 測ってから触る。触ったら測る。**
基準線が無い状態で曲線を変えると、良くなったのか悪くなったのか言えない。

**2. まとめた数字を信じない。**
全体の絶対誤差は 0.5%、出発14日以内は 20.0%（2026-08-24）。出発が遠い
予測は曲線が平坦で当てるのが容易なので、混ぜると誤差が薄まる。
**必ず出発までの日数で分けて見る。**

**3. 推定元と適用先を揃える。**
`price_history` は「その区間で買える最安値」（便を特定しない、日次5.27%）、
`snapshots` は「その便の値段」（日次1.61%）。**別の量。**
便ごとに予測するなら、便ごとの系列から推定する。

**4. 識別できているかを先に見る。**
ある「出発まで◯日」の区間に、出発日が何種類入っているかを数える。
2〜4種類しかなければ、それは曲線の形ではなくその日付の効果。
2026-08-24 の時点では出発14日以内がこの状態だった。

## 毎日、自動で回るもの

日次ジョブ（03:00 PT）が順に:

    収集 → 予測の記録 → **答え合わせ**（app/accuracy.py）→ 通知 → KPI

答え合わせは、対象日を迎えた予測に実測を書き込む（`prediction_log.actual_usd`）。
**その日その便が観測されなかったものは NULL のまま。** 「外した」と
「比べる相手がいない」は違う。

## 毎日、KPI で見る数字

```
prediction_abs_error_pct_near   |予測−実測|/実測 の中央値（出発30日以内）
prediction_bias_pct_near        偏り。**高すぎ/安すぎの向き**
prediction_band_hit_pct_near    実測が信頼帯に入った割合
prediction_samples_near_7d      上の3つの母数
```

**`_near` を見ること。** `_near` の付かない全体値は出発が遠い予測に
薄まる。

### 動いたら何を疑うか

| 症状 | 疑うところ |
|---|---|
| 偏りが +5% を超えて続く | 曲線が高すぎる。直前の形をまず見る |
| 偏りが −5% を下回って続く | 曲線が低すぎる。値上がりを取りこぼしている |
| 帯に入る割合が 70% を切る | `band_ratio` が先読みに対して足りない |
| 母数が急に減った | 収集が落ちたか、便の入れ替わりが増えた |

**1日の動きで判断しない。** 母数が少ない日は振れる。3日続いたら見る。

## 曲線を触るときの手順

### 1. 材料を出す

```bash
sqlite3 flights.db -header -csv "
  SELECT origin, destination, departure_date, return_date, stops, via_airport,
         airline, check_date, price_usd,
         CAST(julianday(departure_date)-julianday(check_date) AS INTEGER) AS days_before
  FROM snapshots WHERE source='real'" > snapshots.csv
```

### 2. 識別できているか確かめる

出発までの日数の区間ごとに、**出発日が何種類あるか**を数える。
少ない区間の数字は使わない。

### 3. 形を復元する

便ごとの系列を二元固定効果（系列効果 ＋ 出発までの日数の効果）で分解する。
素朴に「各系列を自分の平均で割って重ねる」ことはしない — 系列ごとに
見えている区間が違うので、基準がそろわず構成の偏りが傾きに乗る。

### 4. 過去データで当て直す

```bash
python -m scripts.replay_curve --csv snapshots.csv --params candidate.json
```

過去のある日に立って、**その日までの観測だけ**で較正し、先を予測して
実測と比べる。engine と同じ関数を呼ぶので本番と同じ計算になる。

**出発までの日数ごとの表を見て決める。** 全体の数字では判断しない。

### 5. 入れる。そして測り続ける

配備したら、KPI の `_near` 3列を数日追う。**悪化したら戻す。**

## いつ何を測り直すか

| 時期 | 材料 | 測ること |
|---|---|---|
| **2026-11以降** | 調査用系列（片道120）が順次完了 | **谷（50〜59日前 −4.2%）を便ごとに測り直す。** これも `price_history` 由来で、同じ取り違えの可能性がある |
| 2026-11以降 | 同上 | 直前の形。いま出発日が2〜4種類しかない範囲 |
| **2026-10中旬** | 往復系列が出発30日前に入る | **往復の遅延の罰。** 往復に②の通知と判定を出せるかはここで決まる |
| 2026-12以降 | 完了系列が240本規模 | `seasonality` と `day_of_week`。**一度も推定していない** |
| 2027-02以降 | 出発180日前からの完全な系列 | 課題13（機械学習）の着手判断 |

## 手を出してはいけないこと

- **数字だけ合わせに行かない。** 誤差が減っても、推定元と適用先が
  ずれたままなら別の場所で外す
- **`last_minute_peak_factor` を 1.3 より上に戻さない。** 便ごとの実測に
  反する（試験で固定してある）
- **識別できていない区間から形を決めない。** 出発日の種類を数えてから
