# 予測は当たっていたか — 初の突き合わせ（2026-08-24）

課題9。**このアプリの予測が実測と合っているかを測ったのは、これが初めて。**

出発日を迎えて追い切った系列が 2026-08-24 に初めて10本そろい、過去に出した
予測ログと突き合わせられるようになった。

## 材料

```
系列    10本（すべて 2026-08-23 出発、片道、東京 ⇄ 米西海岸）
観測    2026-08-09 〜 2026-08-23（出発14日前〜当日）
予測    350件。うち同じ日・同じ便で実測と対にできたもの 152組
先読み  0〜13日
```

**狭い。** 出発日は1つ、区間は10、しかも**出発14日前より内側しか見ていない**。
以下はこの範囲での結果であって、曲線全体の検証ではない。

## 結果1 — 予測は系統的に高い

| 予測誤差（予測 − 実測） | |
|---|---|
| 中央値 | **+15.3%** |
| 平均 | +18.5% |
| 絶対誤差の中央値 | 17.0% |
| 下位10%〜上位10% | −5% 〜 +42% |

**ばらつきではなく偏り。** 下位10%でも −5% しかなく、ほぼ常に高く出ている。

## 結果2 — 信頼帯が機能していない

**実測が帯に入ったのは 87/152 = 57%。**

| 先読み | 件数 | 絶対誤差の中央値 | 帯に入った | 帯の幅 |
|---|---|---|---|---|
| 1日 | 70 | 9.4% | 80% | 29% |
| 3日 | 51 | 18.4% | 45% | 32% |
| 7日 | 30 | 35.9% | **27%** | 37% |

**誤差は先読みとともに 9% → 36% と4倍になるのに、帯は 29% → 37% しか
広がらない。** 帯は「不確かさの表明」のはずが、遠い予測ほど過信している。

## 結果3 — 原因は「直前の急騰」を想定しすぎていること

出発までの日数で切ると、偏りは直前ほど大きい。

| 出発まで | 誤差の中央値 |
|---|---|
| 13日 | +4.8% |
| 9日 | +15.6% |
| 6日 | +29.7% |
| 1日 | +27.1% |
| **0日** | **+39.9%** |

曲線と実測を並べると、ずれ方がはっきりする。

| 出発まで | **曲線の倍率** | **実測（同一便）** |
|---|---|---|
| 13日 | 1.049 | 1.000 |
| 9日 | 1.243 | 1.000 |
| 5日 | 1.437 | 0.995 |
| 1日 | 1.631 | 1.000 |

**曲線は直前14日で 1.00 → 1.68 と上がるとしているが、同じ便を追うと
ほぼ平坦。** 同一便の対比較でも +5.0%（4/7便, z=+0.4）で、曲線の想定
（同区間で約 +35%）には遠く届かない。

## なぜこうなったか — 曲線の推定元と適用先がずれている

**曲線は `price_history` から推定した**（`scripts/fit_curve.py`）。これは
取得元が持っていた「その検索条件での最安値」で、**便を特定しない。**
安い便が売り切れて消えれば、残った便の値段が動かなくても数字は上がる。

**一方 `build_trend` は、この曲線を便ごとに当てている**
（`(経由回数, 経由地, 航空会社)` で束ねて `price_shape` を掛ける）。

    推定元   ルート最安の推移   … 便の入れ替わりを含む（日次 5.27%）
    適用先   個々の便の推移     … 便を固定（日次 1.61%）

**別の量の形を、別の量に当てている。** このプロジェクトが
`snapshots` と `price_history` を混ぜないよう気をつけてきたのと、
同じ種類の取り違えが曲線側に残っていた。

「出発30日前を過ぎると +16.7%」という既知の結果とも矛盾しない。あれは
**買える最安値が悪化する**という意味で、個々の便が値上がりするという
意味ではなかった。

## 何が言えて、何が言えないか

**言える:**

- この10系列・152組では、予測は中央値 +15.3% 高かった
- 信頼帯は先読みが延びるほど当たらなくなる（7日先で27%）
- 直前ほど偏りが大きく、曲線の直前の急騰が実測に出ていない

**言えない:**

- **これが曲線全体の話かどうか。** 見たのは出発14日前より内側だけで、
  谷（50〜59日前）も遠い側も検証していない
- **同一便の平坦さの確度。** 対比較は n=7便で z=+0.4。方向は見えるが
  「上がらない」と断定できる強さは無い
- 出発日が1つ（2026-08-23）なので、季節や曜日の影響と分けられない

## 利用者への影響

**予測が高く出ると、判定は「いま買え」に寄る。** 将来の最小値が実際より
高く見積もられるため。

**ただし「いま買え」という助言自体が誤りとは限らない。** 個々の便は
平坦でも、買える最安値は悪化する（安い便から売れる）。**結論は偶然
合っていて、理由が間違っている**という状態。

理由が間違っている以上、**金額（予測値と帯）は信用できない。**

## 次に何をするか

1. **`last_minute_*` と `ramp_*` を、完了系列から引き直す。** これらは
   もともと未推定だった（`curve.py` に「出発5日前より内側の観測が1点も
   無い」と書いてある）。いま初めて材料がある
2. **帯の広げ方を見直す。** 先読み7日で27%しか当たらないのは、
   `band_ratio` が先読みに対して足りていない
3. **曲線の推定元を揃えるか、適用先を揃えるか決める。** どちらかしかない
   - 便ごとの系列から曲線を引き直す（`snapshots` を使う。ただし系列が短い）
   - ルート最安に対してだけ曲線を使い、便ごとには当てない
4. 系列が増えたら再測定する。**10本は少なすぎる**

**3が本質。** 1と2は3を決めないまま数字だけ合わせることになる。

## 対応（2026-08-24、同日）

### 便ごとの系列から形を復元した

`snapshots` 3,952系列（0〜224日前）を二元固定効果で分解した。

| 出発まで | 旧曲線 | 便ごとの実測 | 出発日の種類 |
|---|---|---|---|
| 90日 | 0.995 | 0.911 | 多い |
| 60日 | 0.995 | 0.927 | 20 |
| 30日 | 1.095 | 0.918 | 19 |
| 18日 | 1.20 | 0.850 | 4 |
| 5日 | 2.10 | 1.058 | **4** |
| 1日 | 2.43 | 1.052 | **2** |

**30日前より遠くは識別できている**（出発日19〜20種類）。そこで曲線は
+10% 上げるのに、実測は平坦。

**直前は識別できていない。** 0〜14日前は 2026-08-23 が、15〜29日前は
09-08 と 09-12 が大半を占め、出発日の種類が2〜4しかない。日付ごとの効果と
分けられていないので、この範囲の数字は形の推定に使えない。

### 過去データで当て直して決めた

`scripts/replay_curve.py` を作った。過去のある日に立って、**その日までの
観測だけ**で較正し、先の価格を予測して実測と比べる。engine と同じ関数を
呼ぶので本番と同じ計算になる。

| パラメータ | 0-14日前 絶対誤差 | 偏り |
|---|---|---|
| 旧 | 17.4% | +16.9% |
| peak 1.30 | 6.1% | +4.2% |
| **peak 1.10（採用）** | **2.8%** | **+1.7%** |
| peak 1.00（完全平坦） | 0.5% | −0.2% |

**完全平坦が最良だが採らなかった。** 直前の観測が上記のとおり識別できて
いないため、「上がらない」と決めつける側に倒したくない。実測の形
（1〜6日前で約1.05）に合う 1.10 にした。

    ramp_top_factor          1.15 → 1.0
    last_minute_start_factor 1.2  → 1.0
    last_minute_peak_factor  2.5  → 1.10

### 画面の文言も直した

**曲線を平坦にすると、グラフの予測線と文言が矛盾する。** 線は平坦なのに
「値上がりが始まります」と書いてあると、読んだ人はどちらを信じてよいか
分からない。

上がるのは**その区間で買える最安値**であって、追いかけている便ではない。
そう書き直した。「出発30日前で +16.7%」という数字自体は変えていない。

### まだやっていないこと

- **谷（50〜59日前 −4.2%）は便ごとに測り直していない。** これも
  `price_history` 由来なので、同じ取り違えの可能性がある
- **`seasonality` と `day_of_week` は手つかず。** 一度も推定していない
- 直前の形は、調査用系列が完了する2026年12月以降に測り直す
