# 価格の乖離を測る — 手動検証シート（2026-08-15）

課題1（Google Flights の価格に旅行会社の値が混ざる）を、**外部 API を待たずに測る。**

Travelpayouts は採れず（課題12）、Duffel も未確認。だが**測定そのものは今日できる。**
Google Flights の画面には販売元が表示される。API 応答には入っていないが、目視でなら読める。

## 何を測るか

3つの数字を並べる。それだけで判断が付く。

| 列 | 出どころ | 意味 |
|---|---|---|
| **A. 我々の記録** | `snapshots` の 2026-08-15 の値 | アプリが利用者に見せている数字 |
| **B. Google Flights 画面** | 手動で開く | Aと合っているか。**販売元は誰か** |
| **C. 航空会社の直販** | 各社サイト | 実際に買える値 |

- **B − A** … 我々の取得が Google の表示とずれていないか（取得経路の健全性）
- **C − B** … **利用者の不満の正体。** 「Google で見た後に航空会社で調べるともっと高い」の幅
- **B の販売元** … 旅行会社なら、課題1の仮説どおり

## 測定の条件（守らないと比較にならない）

**すべての検索でこれを揃える。**

| 項目 | 値 |
|---|---|
| 旅程 | **片道（one-way）**。我々の記録は片道。往復で見ると別物になる |
| 人数 | 大人1名 |
| 座席 | エコノミー（最安クラス。ZIPAIR なら Standard） |
| 金額 | **税・手数料込みの支払総額。** 運賃だけの表示に惑わされない |
| 通貨 | **US ドル建て・アメリカ発の販売条件で見る** |
| 実施日 | **2026-08-15 中。** 日をまたぐと価格が動き、比較が壊れる |

> **通貨の注意が最重要。** 航空会社サイトは接続元の国で値段が変わる（point of sale）。
> 日本から united.com を開くと円建ての日本市場価格が出て、我々の USD 記録とは
> 別物になる。**サイト上の国・通貨設定を「United States / USD」に切り替えてから**
> 検索すること。切り替えられない場合はその旨を備考に書く。

## 記入時のメモ欄

気づいたことを自由に。特に以下は書き留める価値がある。

- Google Flights が**複数の販売元を並べた**場合、その顔ぶれと価格差
- 「この価格は変更される場合があります」等の**警告表示**
- 直販サイトで**その便が見つからない**（＝満席・非公開在庫）
- 予約クラスや受託手荷物の**条件差**（ZIPAIR は手荷物別料金。総額の定義がずれる）

## この後

記入が済んだら **C − B** の分布を見る。

| 結果 | 意味 |
|---|---|
| 差がほぼ無い | **課題1は実害が小さい。** 外部 API は不要。Duffel も見送れる |
| 数%程度 | 注記で足りる。「実際の販売価格と異なる場合があります」 |
| 十数%以上 | **表示している数字の意味を変える必要がある。** 外部 API を再検討 |

**このアプリの目的は底値の時期を当てることで、金額を当てることではない。**
乖離が一定方向に偏っていれば、水準がずれても**タイミングの判断は保たれる**。
測るべきはそこ — 乖離の大きさより、**乖離が日によって暴れるかどうか**。
