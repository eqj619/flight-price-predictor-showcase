  1. 名前解決。 ブラウザが flights.suosolutions.com を引く。 権威 DNS は Google のネームサーバ（レジストラは Squarespace）で、 AWS の外にある。A レコードが静的 IP を指す。
  2. HTTPS 接続。 443/TCP で Lightsail のファイアウォールを通過する。 80 も開けてあるのは 8 の証明書更新のためで、Caddy が HTTPS へ 308 リダイレクトする。
  3. TLS 終端。 Caddy が証明書を提示し、 X-Forwarded-For を接続元で上書きしてから転送する。 追記のままだとクライアントが偽の IP を名乗り、登録のレート制限を素通りできる。
  4. リバースプロキシ。 127.0.0.1:8000 の uvicorn へ。 アプリは外部ポートを持たない。uvicorn 自身のヘッダ解釈は切ってあり、 ヘッダを信用する箇所をアプリ1か所に集約している。
  5. 読み書き。 FastAPI が SQLite を読み書きする。 モニター・価格履歴・予測ログをすべて同じファイルに持つ。
  6. 価格収集。 毎日 03:00（America/Los_Angeles）にスケジューラが起動し、 Google Flights へ問い合わせる。唯一の外向き通信。 1ルートあたり3検索、2〜5秒の間隔を空けて叩く。
  7. 収集結果の保存。 実測値を snapshots に upsert し、 較正済みの予測を prediction_log に残す。
  8. 証明書の取得と更新。 Caddy が ACME の HTTP-01 チャレンジで Let's Encrypt から証明書を取り、期限前に自動更新する。
  9. バックアップ。 毎日 11:00 UTC（収集の直後）にインスタンス全体の スナップショットを自動取得する。
  10. KPI の書き出し。 収集の直後に、その日の利用状況を1行 CSV に追記し、 S3 へまるごと置き換える。ローカルの CSV が正で、S3 はその写し。 逆にするとアップロードが失敗した日の行が永久に欠ける。 アップロードの失敗は握りつぶす — S3 が落ちていることが価格収集の失敗になってはいけない。
VPC を描いていないのは省略ではない。 Lightsail はネットワークを抽象化しており、 サブネットやルートテーブルを利用者が構成しない。公開範囲はインスタンス単位のファイアウォールで決まる。

日次ジョブの流れ

上図の 6〜7 と 10 を時系列に開いたもの。 順序に意味がある — 整理を収集より先に行う。逆にすると、その日で失効するモニターのために価格を取りに行ってしまう。

Lightsail は無料トライアル中で、2026-06〜08 の課金は実測 $0.00。 上表の $7.00 はトライアル終了後の額で、2026-11 頃から発生する。 費用の逸脱は AWS Budgets で通知する — アカウント全体 $10 / 月と、 Lightsail のみに絞った $12 / 月 の2本。どちらも実績 85%・実績 100%・ 予測 100% の3段階で、2つまでは無料。 プロジェクト用の予算を Lightsail だけに絞っているのは、S3（KPI）が 月 $0.01 未満で誤差にしかならない一方、S3 で絞ると同一アカウントの無関係な バケットが月 $2.5 ほど混ざり、本プロジェクトの異常がその変動に埋もれるため。
先行プロジェクトの Lightsail インスタンス flighttrend（$5.00 / 月）は 2026-08-09 に削除済み。DB を退避したうえで消した — 実測価格の行は 0 件で、 12,400 行はすべてシミュレーション値だったため失うものは無かった。 Lightsail は「停止」では課金が止まらない — 削除が必要で、 アタッチされていない静的 IP も課金対象になる。静的 IP も併せて解放した。
